A cleanup/export step before publishing a page outside the tool. Pairs with squashing the commits. (Jess, 2026-10-12)

Decided (Jess, 2026-10-12): only the agent reads a page's source; people read the rendered page. So the cleanup removes what the tool leaves behind and leaves the formatting alone. It does not reverse the formatter. Indentation, single-line inline runs, single-line SVG, decoded entities, and attribute quoting stay as the formatter wrote them.

Strip:
- directives (<!-- @AI: ... --> comments). Match the way the tool does ('<!-- *@AI:'), not a bare '@AI:', since pages can talk about directives.
- element IDs written into the file. Their shape comes from "Redesign element IDing", hence the blocker.

Leftover directives (Jess, 2026-10-12): strip them and list what was stripped. Don't refuse. The script runs when the user says "good enough", which means any directive still there doesn't matter.

Another reason to run it at "good enough" (Jess, 2026-10-13): parallel iterations on one page collide on element IDs. Two branches each hand out IDs from the same data-hrv-next, so merging them gives two elements the same ID, and the formatter retires both. It happened merging an OVERVIEW loop onto main's mountains: 78 duplicates, repaired by hand by stripping one side's IDs (commit "OVERVIEW: repair the rebase onto main's mountains"). If each loop strips IDs when it ends, the page on main carries none, and the next loop starts fresh.
