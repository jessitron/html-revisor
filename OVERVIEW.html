Step by step

parse, normalize

Parse with linkedom, then rewrite into one canonical shape: add html/head/body if missing, one block per line, inline runs on one line, whitespace collapsed, two-space indent. Idempotent. GET writes the result to disk when it differs.

on disk, before
<h1>Plan</h1>
<p>Ship   the <b>formatter</b>
first.</p><ul><li>one</li><li>two</li></ul>
<img src="map.png">
on disk, after
<!DOCTYPE html>
<html>
  <head></head>
  <body>
    <h1>Plan</h1>
    <p>Ship the <b>formatter</b> first.</p>
    <ul>
      <li>one</li>
      <li>two</li>
    </ul>
    <img src="map.png">
  </body>
</html>

stamp IDs

Every element gets an element ID: data-n, its index in document order. Only in the served copy; never written to disk. Comments are not elements, so adding a note shifts no ID. 

<h1 data-n="3">Plan</h1>
<p data-n="4">Ship the <b data-n="5">formatter</b> first.</p>
<ul data-n="6">
  <li data-n="7">one</li>
  <li data-n="8">two</li>
</ul>
<img data-n="9" src="map.png">

lift notes

Notes come out of the served copy and travel as JSON keyed by element ID. The browser draws them as markers.

on disk
<p>
  <!-- @AI: say why first -->
  Ship the <b>formatter</b> first.
</p>
served
<p data-n="4">Ship the …</p>
…
<script type="application/json" id="hn-notes"
        data-version="3f9a0c1b2d4e">
  {"4":"say why first"}
</script>

inject client

Appended to the served copy after stamping, so none of it gets an ID: a <style> in head; the notes JSON and the client <script> at the end of body. data-version is a hash of the file bytes.

version check

Every PUT carries the version the page loaded with. If the file changed on disk since, the server answers 409 and writes nothing; the tab shows a lasting warning. The client saves 0.4 s after you stop typing, so you hear about it fast.

set texts current

Only for elements whose children are all text. Anything with markup inside gets a comment box only. 

texts: {"3": "Plan B"}     <h1>Plan</h1>  →  <h1>Plan B</h1>
texts: {"4": "…"}          <p>Ship the <b>…  →  refused, unchanged

place notes

The PUT carries every note on the page, so the server removes all notes and writes them back. A note is the element's first child; before a void or raw-text element (img, hr, pre…) it sits just ahead as a sibling. 

<p>
  <!-- @AI: say why first -->
  Ship the <b>formatter</b> first.
</p>
<!-- @AI: needs alt text -->
<img src="map.png">

serialize

Strip the IDs, write the canonical format. What the agent diffs is the human's change, not markup churn.

format directional

The normalize step becomes its own command. The agent runs it after writing the page and fixes what it reports, before the human opens it. The server's GET runs the same code. Validation rules are still to be chosen; one example: 

$ html-notes format OVERVIEW.html
OVERVIEW.html:42  <p> holds a <div>; a paragraph holds phrasing content only

assign IDs directional

Today every tag gets an ID, so <b> inside a paragraph is its own target. Next, a whole prose chunk gets one ID. Open: write IDs into the file? A longer file, but the agent sees the same IDs the browser uses.

today: per element
<p data-n="4">Ship the <b data-n="5">…
headed: per chunk
<p data-n="4">Ship the <b>formatter</b> first.</p>
<ul data-n="5"><li>one</li><li>two</li></ul>

prose as markdown directional

Click a prose chunk: the box shows it as markdown. On save, the PUT carries prose: {"4": "markdown"} and the server turns it back into HTML. Opening and saving without a change must leave the HTML unchanged.

The whole paragraph is one chunk. A heading is its own chunk; a list is one chunk. The text field grows with the text.

Invariants

  • The HTML file is the only record: no database, no notes file beside it, nothing kept in the browser.
  • A note is <!-- @AI: … -->, attached to exactly one element.
  • Formatting is idempotent: a normalized file loads unchanged.
  • An edit never loses markup.
  • A stale tab cannot write (version check, 409).
  • Dependencies point down: orchestration → domain → interface.

Terms

note
A request from the human, stored as an HTML comment starting @AI:. The code says "note"; iterate-on-docs says "comment" and "annotation". To standardize.
normalize
Rewrite the file into canonical shape. See parse, normalize.
element ID
How the browser and server name an element: data-n, assigned by the stamp step.
text element current
Today's unit of editing: an element whose children are only text.
chunk directional
Tomorrow's unit of editing: a piece of prose that converts to markdown as a whole. Candidate term.
phrasing content
HTML-spec term: text plus inline markup (b, a, code…). See MDN: content categories.
