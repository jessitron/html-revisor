format directional

Normalize becomes its own command. The agent runs it after writing the page and fixes what it reports, before the human opens it. GET runs the same code. Validation rules are still to be chosen; one example: 

$ html-revisor format OVERVIEW.html
OVERVIEW.html:42  <p> holds a <div>; a paragraph holds phrasing content only

assign IDs

Every element gets an element ID, data-n: its index in document order. Served copy only. HTML comments are not elements, so adding a directive shifts no ID.

The whole paragraph is one prose chunk. A heading is its own; a list is one. The text field grows with the text.

Invariants

  • The HTML file is the only record: no database, no file beside it, nothing kept in the browser.
  • A directive is <!-- @AI: … -->, attached to exactly one element.
  • Formatting is idempotent: a normalized file loads unchanged.
  • A stale tab cannot write (version check, 409).
  • Dependencies point down: orchestration → domain → interface.

Terms

directive
A request from the human to the agent, stored as an HTML comment starting @AI:. Avoid: note, comment, annotation.
normalize
Rewrite the file into canonical shape. See parse, normalize.
element ID
How the browser and server name an element: data-n, assigned by the stamp step.
text element current
Today's unit of editing: an element whose children are only text.
prose chunk directional
Tomorrow's unit of editing: prose that converts to markdown as a whole.
Contract
What iterate-on-docs relies on, words included: the table in README. See how it reaches you.
deploy, release
Deploy copies main into iterate-on-docs. Release, run there, versions and publishes it. A deploy is not a release.
phrasing content
HTML-spec term: text plus inline markup (b, a, code…). See MDN: content categories.
