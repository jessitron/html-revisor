format directional

Normalize is its own command, in formatter.mjs; GET runs the same code. The agent runs it after writing the page, before the human opens it. Directional: validation rules, for what normalizing can't fix. None yet; one a rule could report: 

$ node formatter.mjs OVERVIEW.html
OVERVIEW.html: <p> holds a <div>; a paragraph holds phrasing content only
assign IDs

One element ID per scope (every block), and per link, image, hr, and part of an SVG. The formatter writes them into the file, from a counter whose high-water mark sits on <html>, so an edit can't shift them. It assigns IDs on every GET and first thing on every PUT. An ID never changes and is never reused; duplicates (an agent's copy-paste) retire the ID, and every copy gets a fresh one.

The green lines exist only in the served copy, never in the file, so the client's own elements have no ID and can't take a directive. data-version fingerprints the file on disk; a save's answer says whether the file changed (see conflict check). hrv-bases holds each element's base, which a save sends back.

browser
PUT page.html {id, base, directive} or {id, base, markdown}
browser

Sent 0.4 s after you stop typing. Carries one change, a directive or a scope's markdown, with the base it started from. Changes go out one at a time.

conflict check

No file-wide version. The server compares the change's base with the element now, directives and IDs stripped. Only that change can conflict. A changed child changes its parent, so nesting needs no special case. 

{id: "6", base: "a1c4", directive: "say more"}
  base matches li 6        →  applied; answer has new bases
  base differs, or no li 6 →  412, nothing written: error, reload suggested

A conflict means we weren't taking turns; it's an edge case. An agent's edit elsewhere doesn't block the save. The answer carries the file's hash before the save; if that isn't the page the tab loaded, the tab says "the page changed on disk; reload to see it". directional Later the tab hears of it live.

set prose
{id: "4", base, markdown: "Ship the **formatter** last."}
  →  <p data-hrv="4">Ship the <strong>formatter</strong> last.</p>

Any scope. The answer carries the new HTML, as served, and the new markdown of the scopes around it; the tab swaps the HTML in. Blank markdown, body, and elements that aren't scopes (hr, an SVG shape) are refused.

Open, then save unchanged: the HTML stays byte-for-byte the same. See Prose editing.

Saving reconciles with the prior HTML: an element the edit leaves alone, moves, or changes keeps its ID and what markdown can't say (img width and height). New elements get fresh IDs, sent back to the tab.

place directive

A save carries one directive; empty text removes it. The rest stay where they are, so a directive the agent finished and removed can't come back. First child of its element; before a void or raw-text element (img, hr, pre…).

Pick the paragraph, the list, one item, or the section around them: each is a scope and edits as markdown. Saving sends the markdown; the server answers with the HTML, and the page swaps it in. Elements you left or changed keep their IDs and directives.

Invariants

  • The HTML file is the only record: no database, no file beside it, nothing kept in the browser.
  • A directive is <!-- @AI: … -->, attached to exactly one element.
  • Formatting is idempotent: a normalized file loads unchanged.
  • A save can't overwrite an element its tab didn't see (conflict check).
  • An element ID never changes and is never reused.
  • Dependencies point down: orchestration → domain → interface.

Terms

directive
A request from the human to the agent, stored as an HTML comment starting @AI:. Avoid: note, comment, annotation.
normalize
Rewrite the file into canonical shape. See parse, normalize.
element ID
How the browser and server name an element: data-hrv, written into the file by assign IDs.
scope
The unit of editing and directives: any block you pick, plus links, images, and spans, edited as markdown as a whole. Scopes nest.
Contract
What iterate-on-docs relies on, words included: the table in README. See how it reaches you.
deploy, release
Deploy copies main into iterate-on-docs. Release, run there, versions and publishes it. A deploy is not a release.
phrasing content
HTML-spec term: text plus inline markup (b, a, code…). See MDN: content categories.
