Decided (Jess, 2026-10-12): write IDs into the file. This replaces the earlier "keep IDs out of the file unless implementation finds a use for it": the use is text editing at several levels, where an edit adds or removes elements (add a list item, delete an inline image). Positional IDs (index or tree path) shift on those edits; only an ID stored in the file gives an element an identity.

Shape (proposed): data-hrv="<short value>" from a counter, never positional, so inserting an element doesn't renumber the rest. Possibly only on addressable elements (chunks). The formatter assigns missing IDs and resolves duplicates. Contract change in iterate-on-docs: agents leave data-hrv alone. One noisy diff per file on first format is fine.

Rule: IDs are stable for one version of the file. A reformat may re-establish IDs (dedupe) and that bumps the version, so the tab gets a 409. Adding an ID to a new element changes no existing ID and should not bump it. So "version" stops meaning a hash of the bytes; see the version question below.

Export: the cleanup yak (cleanup-script-...-41o3) strips the IDs.
