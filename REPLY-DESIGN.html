html-revisor: reply design

The agent answers in the page. Each element carries its own small conversation, and many run at once while you keep reviewing.

Where it stands

An agent replies today with node reply.mjs <page URL> <id> <thread> <text>, the id and thread from the Announcement. The reply shows after a reload. The “built” column in Decided marks each decision the code has.

Flow

One directive, start to answer. The Announcement on stdout already exists; the rest is new. Magenta arrows are the server pushing to the tab.

Directive box with a thread

Until the agent replies, the box is today's: Content, Directive, Done. Once it replies, the directive becomes the first turn in the thread, and the field below the thread takes your answer. You read top to bottom and type at the bottom. A rule at the left of each turn says whose it is, magenta yours and green the agent's, and the words “you” and “agent” say it too. Content is monospace; directives, turns, and replies are prose. The thread grows to 240px, then scrolls, and opens scrolled to the end.

Answered. Two rounds; you're typing a third turn. Done sends it, the same as today. Clear empties the turn you're typing. Resolve, beside Done, ends the thread: it removes the directive and its replies. The thread needs no label: the turns say whose they are.

Once the agent has a directive, the directive stays as you wrote it, and you add a turn instead. That keeps it from changing under the agent. A turn you add while the agent works will give it a stale notification, and then it can notice what you said and post its update again.

Marker

The tile stays: near-black, light ring, square. The glyph on it changes with the state, and nothing moves. The cycle ends where it began, so the magenta pencil stays the usual sight.

  • Waiting: today's magenta pencil. Your directive, no reply yet.
  • Unread answer: a green speech bubble. A reply you haven't opened.
  • Opened: back to the magenta pencil. The thread is still there, and the docket's directives step to it.

The grounds and the color-blind check draw working too, a state for later, so every glyph is tested together.

What it shows. Green alone fails. Under deuteranopia, the most common kind, the magenta turns khaki (#878168) and the green turns a lighter khaki (#c2b36e): the two pencils differ in lightness alone, and a 14px glyph beside busy page text doesn't hold that difference at a glance. So the shape carries the state and the color backs it up. This green, #51cf66, kept the most distance from the magenta of five greens under protanopia and deuteranopia, and it is lighter than the magenta, which helps in greyscale. The bubble changes the whole glyph, so it reads at 14px in any vision; the badge's 8px square gets lost beside a neighbor marker.

Docket

Two rows. The top row counts directives: every open thread. The bottom row counts new replies: the ones you haven't opened. Opening a reply's box takes it off the bottom row; its thread stays in the top one. ⌥↑ and ⌥↓ step through directives, as today. The replies row has its own arrows. Stepping to a reply works as stepping to a directive: the element scrolls to the middle, shows its crop marks, and its marker shows its tip.

question answer built see
Where do replies live? In the page's HTML file, as HTML comments beside the directive, outside the element's content hash. A reply goes after the last turn in the thread, and the whole thread sits where a directive does: a run of turns before an image or a pre is that element's, so its parent's thread goes last. Cleanup removes them. ✓
Who writes the live file? The server, and it should be the only process that does. The agent hands it replies and status through a CLI that calls the running server, so the server orders the agent's writes with the browser's saves. ✓ flow
Who commits? The agent, each time it adds a reply, in whatever way it commits. The server never commits. A commit may catch half an edit of yours; the next one picks up the rest. So every turn is in history before Resolve removes its thread. flow
What is a turn now? A point to diff from. The agent notes the commit at the last turn boundary, so a diff from it shows every edit and directive since. That's a backup: the agent already hears each one from the server's output.
What if the directive changes while the agent replies? The server refuses the agent's write as stale, the same way it refuses a browser save on an element that changed. ✓
How does the tab learn of a reply? The server pushes each change it makes to the open tab. It also watches the file, for a write that goes around it. flow
Where does a reply show? In the box, below the directive: a thread, one per element. on reload box
How do you answer a reply? Add a turn to the thread. The directive stays as you wrote it. ✓ box
Which type is monospace? Content alone. Directives, your turns, and replies are prose. ✓ box
How do you know the agent has it? When it replies. The marker cycles: magenta pencil, green bubble for an unread answer, and back to the pencil once you open it. A working state comes later. on reload marker
Does anything move? No. Nothing blinks or pulses. ✓ marker
Whose color is whose? Magenta is yours, green the agent's. The glyph's shape and the words “you” and “agent” say it too, so color is never the only cue. DESIGN.html's palette changes to match when this ships. ✓ marker
What does a hover show? Whatever was said last in the thread. ✓ marker
What does the docket count? Two rows. Directives: every open thread. New replies: the ones you haven't opened. ⌥↑ and ⌥↓ step through directives. top row docket
How does a thread end? You end it, with Resolve beside Done. It removes the directive and its replies. Clear, on your field, empties the turn you haven't sent. ✓ box
Does the agent end a thread? No. When it has nothing more to say, it replies 👍.
What if you add a turn while the agent works? The agent sees it the next time it reads the server's output. Its reply comes back stale; it reads your turn and replies again. flow
How does the file tell whose turn is whose? By the prefix, which names who the words are for. Your turns are <!-- @AI: … -->, as directives are today. The agent's replies are <!-- @Human: … -->. A thread is the run of them beside the element, in order. ✓
What changes in the Contract? The @Human prefix, the CLI that writes a reply, and the words you see: reply, new replies, Resolve. README only
What can get a reply? A directive. Replies on edits come later. ✓ later
