Architecture and code quality

An assessment of html-revisor as of 2026-10-25: 4,300 lines of our own code, 239 tests in 8 seconds. What holds up, where the weight sits, and five recommendations.

Verdict

The bones are good. The tier rules are executable, the domain is pure, the file is the only source of truth, and the concurrency model fits on an index card. The trouble is weight distribution: three files carry most of the change, and each holds more than one idea.

Holds up Strains
  • test/architecture.test.mjs enforces tiers, purity, and no cycles. Rare, and worth more than any diagram.
  • One writer, one turn per file (oneAtATime), optimistic checks by base. Simple and correct.
  • Round-trip tests on real pages and seeded generated edits catch fidelity bugs no example would.
  • Comments say why. Names come from the domain: directive, scope, base, thread, spill.
  • Telemetry on every step, with Honeycomb queries documented.
  • The save rules live in server.mjs, Tier I, the most-changed file.
  • domain/scopes.mjs is four modules in one, and identity.mjs reaches into it.
  • client.js keeps the sync protocol in 20 loose variables beside DOM code.
  • The wire protocol has three written copies and no single owner.
  • No context map: the agent writing the file around the server is a boundary nobody drew.

Recommendations

# Change Payoff Effort Mountain
1 Move the save rules into the domain high medium fidelity
2 Split scopes.mjs by idea high low fidelity
3 Give the client's sync protocol a home without a DOM high high fidelity, ergonomics
4 One owner for the wire protocol medium low upkeep
5 Small cleanups low low upkeep

1 · Move the save rules into the domain

applyChange in server.mjs is 80 lines, and most of them are domain rules: a base that doesn't match is a conflict, a spill that moved is a conflict, a reply since is a conflict, a grown scope loses its markdown. Tier I decides all of that today. That is why server.mjs changed in 44 commits since September, more than any other file.

  • Tests of conflict rules move from acceptance (HTTP, temp files) to plain function calls. Faster, and closer to the rule.
  • Telemetry: the domain can't import interface/telemetry.mjs. Pass a step(name, fn) function in; it defaults to (n, f) => f(). This is a port in the DDD sense, and it keeps the spans OBSERVABILITY.html queries.
  • Makes Rethink who edits the live file cheaper: whatever the answer, it needs the rules in one place.

2 · Split scopes.mjs by idea

806 lines, four ideas, and most open fidelity yaks land here: link pairing, tables, inline fallback, button text, blank lines. identity.mjs imports canonicalHTML, isBlock, and hasAttrs from it, so the module that "knows nothing of IDs" sits under the one that assigns them. Two modules each define a BLOCK set, and the sets differ: canonical's means "laid out on its own line", scopes' means "a block you can pick".

Mechanical, covered by the round-trip tests, and it lets two fidelity yaks run in parallel without colliding in one file. Do it before the next round of table and link work. CLAUDE.md warns about parallel branches that move code between domain modules: do this one alone.

3 · Give the client's sync protocol a home without a DOM

client.js is the largest file, and its hardest part has no shape: twenty top-level variables that together are a state machine for "what the file holds, what this tab typed, what's in flight, what came back". Every client test drives it through a linkedom tab with a faked focus model and a fast clock, and four CLAUDE.md gotchas are about that harness.

  • No build step needed: the server already reads client.js on each GET. Let it read client/*.js in a listed order and inline them as one script. Each file adds to one namespace.
  • The sync object is where the yaks urgent: notify if the server is down, Live notice shows content edited on disk, and A half-typed save can drop a directive land. They get cheaper to build and to test.
  • Largest effort here. Worth a design pass in REPLY-DESIGN style first.

4 · One owner for the wire protocol

The PUT, POST, and SSE shapes are written out three times: README's Design section (one bullet runs past 600 words), the comments over putChange and postDone, and the 400 error messages, which describe the shapes by hand. Each change to the protocol touches all three, plus client.js.

  • The validators move to the domain with recommendation 1, each beside the shape it checks. The error message comes from the same place.
  • README keeps one short table of the shapes and links the module, the way it links SCOPES-DESIGN for scope rules. The Design section gets bullets a person can read in one breath.

5 · Small cleanups

  • server.mjs imports formatFiles from formatter.mjs, Tier I to Tier I. The rule allows it, but it makes one entry point a library of another. Fine as is; name it in the architecture test's comment so it reads as chosen.
  • parse(onDisk) then assignIds, three times in server.mjs. Folds into readRevision with recommendation 1.
  • The constants STAND_IN, STOPS, FROM_MARKDOWN sit at the end of scopes.mjs, after the code that uses them. They move with the split.
  • Three fingerprints share the word "base" and its cousins: version (the file), base (an element), thread base (a thread). Clear in the code; worth one line in the context map so the tab and agent sides keep them apart.

Leave these alone

  • oneAtATime: twelve lines, and it makes the whole concurrency story true.
  • The architecture test. Extend it when the split lands (a rule for "report code stays out of the core scope module", if it earns one), but don't loosen it.
  • Files as the only truth, and the right to rewrite them. It's what keeps the tool small.
  • The vendored bundles. They cost 700 KB of repo and buy running behind a proxy.

Suggested order
