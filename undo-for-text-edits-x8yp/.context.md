REVERT
- Name: Revert. Goes back to the LAST COMMIT of the file, not the page load: a reload (the panic move) doesn't lose it, and in an iterate loop the last commit is the start of the turn.
- Place: right end of the Content label's line in the scope box. Shown only when the scope's content differs from the commit.
- Action: writes the committed markdown into the Content field as if typed (select all + document.execCommand('insertText')), so it saves like typing and Cmd-Z undoes the revert. No new save path.
- A deleted element comes back by reverting the scope around it. Reverts content only; directives untouched. No page-wide revert (git checkout does that).
- Finding the scope in the commit: match by data-hrv. For a commit without IDs, run the formatter on the committed copy; it numbers a page the same way every time (checked: OVERVIEW formats byte-identical twice), so the numbers match the page as first opened if the file was unchanged since the commit. A scope with no match gets no Revert. The server must send each scope's committed markdown (e.g. beside the hrv-markdown payload on GET): server.mjs and client.js together.

CLEAR (Delete renamed)
- Delete becomes Clear: an x reads as closing the box, and what it does is empty the directive. Same hotkey; tooltip "Clear the directive (⌥⌘⌫)".
- Place: right end of a Directive label line, shown only when there is a directive. The PLAIN directive box gets that Directive label line too, so Clear sits in one place in both boxes.
- Footer becomes just the status ("saved" etc.) and Done.
