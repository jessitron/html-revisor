Prose chunks

The rule from stage 2, in code. Today's “text element” is the plain-text case of it.

  • isProseChunk(el) replaces isTextElement; the client marks chunks editable
  • Element identity: a save that adds or removes an element inside a chunk shifts the data-n of every element after it. The client keeps its old stamps today. Restamp after save, or key some other way. IDs stay out of the file. a17m
4

HTML ⇄ markdown round-trip

CommonMark passes raw inline HTML through, so any chunk can be markdown. Opening a chunk and saving it unchanged must leave the file unchanged.

  • Canonical tags: the formatter rewrites b→strong, i→em, so markdown's one syntax maps back to one tag. The first validation rule.
  • A property test: chunk → markdown → chunk is identity. Watch * _ ` [ escaping.
  • Directives on elements inside the chunk ride along as raw <!-- @AI: … --> in the markdown, and come back on save.
  • Libraries: a markdown parser and an HTML-to-markdown writer, vendored like linkedom
Where does conversion run: server or client? Keying is the same either way: the chunk's data-n. The difference: the server has the file with directives in place, so its markdown carries them. The client's page has them lifted out into JSON. The client gives a live preview.
