Rule (Jess, 2026-10-12): any element that can take a comment sits on its own line, so the comment is clearly tied to it.

Today: stamp gives a data-n to every element inside an <svg> (rect, text, tspan, path). The client targets closest('[data-n]'), so a click comments on the inner piece, and that note lands inside a one-line SVG. An svg <text> probably passes isTextElement, so it's text-editable too.

Want: only the <svg> as a whole is commentable (and not text-editable inside). Keep it on one line; SVGs aren't diffed. Commenting on parts of an SVG is its own subdomain; not now.
