The agent answers a directive or an edit in the page, so Jess never leaves the browser. Each element carries its own small conversation; many run in parallel while Jess keeps reviewing. Jess, 2026-10-19.

Decided:
- Replies live in the source HTML file, like directives. Committed with the turn; cleanup removes them.
- The server writes them, not the agent's hand. The server serializes the agent's writes with Jess's saves, so either side can get a stale error: Jess changing a directive while the agent replies to it refuses the agent's write.
- The agent writes through the running server (a CLI that calls it), which then chooses how to tell the open tab.
- Replies show in the box, below the directive.
- Status on a directive: working, answered.
- Docket counts both: N directives · M replies.
- Edits get replies too, from the revision Announcement: 'I also changed 3 other places that used the old word', 'Want me to update the other documents to match?'

Starting point: the Announcement on stdout already lets an agent start on a directive while Jess keeps working (Monitor on lines starting with {).
