Found 2026-10-13 on the parent's test page, test/pages/mintlify-animal-fables.html (320 KB, 717 scopes, divs nested ~12 deep). This is the lag Jess saw while typing. Numbers from a manual first look; telemetry sets the real baseline.

- One markdown PUT on p 434: ~7 s, answer 1.6 MB. Nearly all of it is 'markdowns' for 10 enclosing scopes (up to 288 KB each).
- In process: rendering those ancestors' markdown ~5 s (the outermost divs ~1.4 s, ~1.3 s, ~0.9 s ...). Everything else in the PUT (parse, save, serialize, re-parse, bases) ~110 ms.
- GET is the same: ~7.7 s, 3.4 MB, because it injects every scope's markdown.
- With a 7 s save, Done closes the box and the page catches up 7+ s later; a reload in that window loses the edit; typing piles up behind one slow PUT.

Proposal: the client asks for one scope's markdown when its box opens (GET ?markdown=<id> or similar). PUT and GET stop sending markdowns. That also fixes staleness: a parent's markdown is read fresh after a child's save.
Whether a 288 KB wrapper div should be a scope at all is its own yak: 'Limit the size of what counts as a scope'.
