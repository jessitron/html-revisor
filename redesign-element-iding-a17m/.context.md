Decided (Jess, 2026-10-12): write element IDs into the file. Positional IDs (index or tree path) shift when an edit adds or removes elements; scopes nest and edit as markdown, so that happens all the time. Scopes (ckba) wait on this.

IDs
- data-hrv="<n>" from a counter; the high-water mark lives in the file (e.g. <html data-hrv-next="214">). Short IDs.
- Never reuse an ID. On duplicates the formatter retires the ID: every copy gets a fresh one.
- The formatter assigns IDs on every GET, and first thing on every PUT (an agent may have added elements since). Existing IDs never change.
- First format of each file is one noisy diff. Fine.
- Contract change: iterate-on-docs agents leave data-hrv and data-hrv-next alone. Make the matching edits there.
- Export: cleanup yak (41o3) strips them.

Saves: no file-wide version, no 409
- Text edit: {id, base, new}. Applies if the scope's current content matches base; compare with directives and data-hrv stripped, so the formatter adding IDs isn't a change. A changed child changes its parent's content, so nesting needs no special case. base can be a hash.
- Directive edit: one at a time, {id, base, text}; empty text removes. No full set (it would resurrect directives an agent finished).
- Server assigns IDs to elements an edit adds and returns them to the tab.
- Conflict (base mismatch, or missing ID) is an edge case: turn-taking broke. Show an error, suggest reload (cqsh). Nothing more.
- The tab learns of outside changes by a notice, not a block (0so7 on save, b0zb live).
