Summary of the design, as of 2026-10-20:
- Turns are HTML comments beside the element, outside the content hash; the prefix names who they're for: Jess's turns @AI, the agent's replies @Human. Cleanup removes both.
- The server should be the only writer of the live file. The agent writes replies and status through a CLI that calls the server; the server pushes its own changes to the tab and watches the file for writes that go around it.
- Box: a thread, no label. Answering adds a turn; the directive stays as written. A turn added while the agent works makes its reply stale; it rereads and replies again. Content alone is monospace.
- Marker cycles: magenta pencil, green bubble (unread answer), back to the pencil once opened. Nothing moves.
- Docket: two stacked rows, directives (every open thread) over new replies (unread). Arrow keys step directives. Hover shows the last word.
- Only Jess ends a thread, with Resolve beside Done. The agent replies 👍 when it has nothing more. Clear empties her unsent turn.
- Out of scope: working status (designed, REPLY-DESIGN #working), replies on edits, links between elements, yes/no buttons.
- The agent commits the file each time it adds a reply, in whatever way it commits; the server never commits. Half an edit in a commit is fine. A turn is a point to diff from: the agent notes the commit at the last turn boundary, a backup to the server's output.

Open (see REPLY-DESIGN #open): a want-a-reply checkbox, later.
