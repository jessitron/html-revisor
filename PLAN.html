2

Decide what makes a chunk

Which elements belong to a prose chunk, and which start a new one. Phrasing content (text, strong, a, code…) belongs. Lists, code blocks, and other containers get decided here too, not later.

  • A tool for deciding: example HTML in, chunk boundaries out, so we can look at the cases
  • A set of examples: started in try-me.html, cases A1–F3. Add shapes from real overview pages.
  • Nonprose inside prose: an <svg> in a paragraph, a code block in a list item. How does it appear in the markdown? The answer sets when we build it.
3

Prose chunks

The rule from stage 2, in code. A chunk is the unit of editing and of directives. Elements inside it get no data-n, no hover, and no directives.

  • isProseChunk(el) replaces isTextElement; the client marks chunks editable
  • Stamping skips inner elements, so a prose edit that adds a <strong> shifts no one's data-n. An edit that adds or removes a nonprose chunk inside prose still would; stage 2 decides whether that happens. IDs stay out of the file. a17m
  • A directive already on an inner element: the formatter moves it up to its chunk
4

HTML ⇄ markdown round-trip

CommonMark passes raw inline HTML through, so any chunk can be markdown. Opening a chunk and saving it unchanged must leave the file unchanged.

  • Canonical tags: the formatter rewrites b→strong, i→em, so markdown's one syntax maps back to one tag. The first validation rule.
  • A property test: chunk → markdown → chunk is identity. Watch * _ ` [ escaping.
  • Libraries: a markdown parser and an HTML-to-markdown writer, vendored like linkedom
Where does conversion run: server or client? With no directives inside a chunk, either side has all it needs, and both key by the chunk's data-n. Server: the client stays small. Client: a live preview.
