The agent answers a directive in the page, so Jess never leaves the browser. Each element carries its own small conversation; many run in parallel while Jess keeps reviewing. Jess, 2026-10-19.

The design lives in REPLY-DESIGN.html: its Decided table, flow, prototypes, and open questions are the source. Summary as of 2026-10-20:
- A reply is a second HTML comment beside the directive, outside the content hash. Cleanup removes it.
- The server should be the only writer of the live file. The agent writes replies and status through a CLI that calls the server; the server pushes its own changes to the tab and watches the file for writes that go around it.
- Box: a thread below the directive. Answering adds a turn; the directive stays as written. Content alone is monospace.
- Marker cycles: magenta pencil, green working squares, green bubble (unopened reply), back to the pencil once opened. Nothing moves.
- Docket: two stacked rows, directives (every open thread) over new replies (unopened). Arrow keys step directives. Hover shows the last word.
- Clear, on the field you type in, ends a thread.
- Out of scope: replies on edits, links between elements, yes/no buttons.

Starting point: the Announcement on stdout already lets an agent start on a directive while Jess keeps working (Monitor on lines starting with {).
